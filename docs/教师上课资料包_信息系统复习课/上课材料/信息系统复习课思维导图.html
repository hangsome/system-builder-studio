信息系统框架

五个要素
硬件、软件、数据、通信网络、用户。结合具体情境判断各部分对应的设备、数据和人员。
系统功能
输入温度数据，处理阈值，输出报警和页面，存储历史记录，支持查询。
用户范围
信息技术小组负责搭建维护，食堂值班人员用手机或浏览器查看，教师可查看后台证据。
开发模式
B/S 模式 通过浏览器访问服务器，用户端一般不需要安装专门客户端；C/S 模式 需要客户端程序与服务器端程序配合运行。
前期准备
先做必要性和可行性分析，再确定硬件、软件、网络、数据库和页面输出方式。
2

硬件清单与扩展板引脚

传感设备
温湿度传感器负责采集温度，是输入设备；数据线连接到扩展板输入引脚，如 pin1。
执行器
蜂鸣器接收控制信号后发声；控制线连接到扩展板输出引脚，如 pin2。
智能终端
micro:bit + 扩展板运行程序，完成读取、判断、控制和组织上传数据。
网络设备
IoT 模块接入无线网络，WiFi 路由器提供通信环境，让数据能传到服务器。
服务与查看
普通 PC 可作为 Flask 服务器；SQLite 保存记录；浏览器或手机是用户查看入口。
3

软件分工读重点

读模拟量
pin1.read_analog() 通过 pin1 引脚读取模拟量，常用于读取传感器输出的连续变化数值。
写数字量
pin2.write_digital(1/0) 通过 pin2 引脚输出数字量，用 1 或 0 控制执行器的开关状态。
阈值判断
判断当前温度是否超过安全阈值，再决定是否报警；学生要会说清“判断依据”。
上传数据
智能终端用 GET 访问上传 URL，把采集结果作为参数发送给服务器。
设置路由
@app.route('/upload') 把 URL 路径和处理函数对应起来，用于接收指定地址的请求。
读取参数
request.args.get() 从 GET 请求的 URL 参数中取值，例如读取传感器编号和采集值。
写入数据
INSERT INTO sensorlog 把新记录写入数据表，便于后续查询、统计和排错。
页面呈现
render_template(...) 把查询结果交给网页模板，生成浏览器能看到的页面。
4

数据流与两类 URL

上传 URL
智能终端 -> 服务器：http://192.168.1.100:5000/upload?id=1&val=32.5
查看 URL
浏览器或手机 -> 服务器：http://192.168.1.100:5000/
参数含义
id 是传感器编号，val 是温度值；服务器按参数接收和保存。
路由作用
路由决定服务器调用哪个处理函数；上传数据和查看页面通常使用不同路由。
数据留痕
SQLite 的 sensorlog 记录温度、报警状态、时间戳，是判断系统是否跑通的证据。
5

按现象选择排错路径

先描述看到的现象，再缩小到具体环节。

没有新记录
现象：运行后日志没有 GET /upload，sensorlog 没有新增行。
查：读取引脚是否有值 -> 上传 URL 是否完整 -> IoT/WiFi 是否连通 -> Flask 上传路由是否存在。
记录有，蜂鸣器无响应
现象：数据库已有 32.5℃ 记录，但超过阈值时现场没有声音。
查：阈值判断结果 -> 代码是否向控制引脚输出 -> 扩展板输出引脚与执行器控制线是否对应 -> 执行器控制信号是否到达。
记录有，页面看不到
现象：数据库或后台能看到温度，浏览器首页空白、报错或地址打不开。
查：浏览器是否访问 / -> Flask 首页路由 -> 数据库查询 -> 模板渲染。
6

排错与测试方法

答题顺序
先描述现象，再定位环节，最后提出检查项。例：页面无数据 -> 查看 URL / 路由 / 数据库查询。
硬件测试
检查传感器、执行器、扩展板引脚和接线是否对应；输入设备看采集值，输出设备看响应动作。
软件测试
检查程序逻辑、阈值判断、路由、URL 参数、数据库写入和页面显示是否符合预期。
网络测试
检查设备是否接入同一网络，服务器 IP、端口、路由是否正确，请求是否到达服务器。
证据来源
用运行日志、数据库记录、页面显示、接线情况和测试记录支撑判断，避免只写笼统原因。
