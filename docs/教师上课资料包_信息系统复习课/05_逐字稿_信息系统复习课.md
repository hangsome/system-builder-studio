# 信息系统复习课逐字稿

课题：存储间温度监测与预警信息系统
建议时长：40-45 分钟
课堂定位：复习课。用一个完整项目把“人、硬件、软件、网络、数据”串起来，重点突破代码阅读、数据流分析和故障排查。
教师投屏建议：活动页、学生半成品画布、教师后台只在需要时切换展示。
学生入口：http://159.75.213.93/system-builder/openclass
活动页：http://159.75.213.93/activity-submit/activity

## 0. 课前准备

教师提前打开：

1. 学生半成品画布入口，确认默认只显示智能终端、IoT 模块、无线路由器、Web 服务器、SQL 数据库。
2. 活动页，确认硬件搭建、软件分析、运行排错、知识总结四个环节可切换。
3. 教师后台，只在教师电脑保留，不投给学生看密码页面。
4. 导学案，提醒学生平台活动用于操作，导学案用于记录结论。

课堂统一口径：

- micro:bit + 扩展板统称为“智能终端”。
- IoT 模块单独保留，不并入智能终端。
- 不直接告诉学生完整浏览器地址和排错答案，先让学生从画布、代码和日志中推出来。
- 排错时统一说法：先看画布实际接线，再看代码引脚是否一致，最后沿数据流继续排查。

## 一、情境导入：从需求倒推设备（约 2 分钟）

教师：

> 同学们，今天我们复习“信息系统”。这节课不是直接背概念，而是用一个真实的存储间温度监测问题，把信息系统从硬件、程序、网络、数据到排错完整走一遍。

教师：

> 去年秋季，某中学食堂遇到过一次险情。早餐食材晚上存放在配餐间，工作人员下班后无人值守。一天半夜，制冷设备发生故障，第二天早上食材温度异常升高，存在变质风险，差点影响全校早餐供应。

教师：

> 后来，学校信息技术小组自己搭建了一套“存储间温度监测与预警系统”：温度自动采集，不需要人员夜间留守；当温度超过安全阈值时，现场要发出声音提醒，并通过网络把异常信息传到服务器；值班人员用手机或浏览器访问服务器页面，就能查看实时温度和历史记录。

教师提问：

> 请大家先不说设备名称，先说需求。这个系统最先要感知什么变化？

预期学生：温度变化。

教师追问：

> 要获得温度变化，需要哪一类传感器？

预期学生：温度传感器、温湿度传感器。

教师追问：

> 温度过高时，要在现场发出声音提醒，需要哪一类执行器？

预期学生：蜂鸣器。

教师总结：

> 很好。传感器负责“感知”，执行器负责“动作”。但一个信息系统不只有传感器和执行器，它还需要运行程序的智能终端、负责联网的 IoT 模块、网络设备、服务器、数据库，以及使用和维护系统的人。今天我们就用这个项目复习信息系统五个组成部分：人、硬件、软件、网络、数据。

板书：

> 信息系统 = 人 + 硬件 + 软件 + 网络 + 数据

## 二、硬件搭建：先补关键组件，再看信息流（约 8-10 分钟）

教师打开学生半成品画布和活动页“硬件搭建”。

教师：

> 现在看画布。半成品已经给出主链路：智能终端、IoT 模块、无线路由器、Web 服务器、SQL 数据库。注意，课堂中 micro:bit 加扩展板统称为“智能终端”。默认隐藏细节时，我们先把它看成一整块能读传感器、控执行器、运行程序的板。

教师提问：

> 画布现在还缺少哪两个和情境直接相关的组件？

预期学生：温湿度传感器、蜂鸣器。

教师：

> 请大家从组件库拖入温湿度传感器和蜂鸣器。拖入后先不要急着运行，观察它们自动连到了智能终端的哪个引脚。

学生操作：拖入温湿度传感器和蜂鸣器，必要时点击“一键优化布局”。

教师巡视点拨：

> 传感器看 DATA，蜂鸣器看 IO。电源细节现在默认隐藏，我们先把注意力放在数据线和控制线上。

教师提问：

> 温湿度传感器的 DATA 接到智能终端哪个引脚？蜂鸣器的 IO 接到哪个引脚？

预期学生：DATA 接 P1，蜂鸣器 IO 接 P2。

教师：

> 这个结论要写到导学案。后面排错时，如果代码里读取或控制的引脚和这里不一致，系统就可能出现“没有数据”或“蜂鸣器不响”。

教师切换到活动页硬件搭建的模块功能匹配题。

教师：

> 接下来不是再背设备名称，而是看“谁负责什么”。读取温度、判断是否超过阈值、控制蜂鸣器，这些在智能终端程序里完成；通过 WiFi 发送 HTTP 请求，由 IoT 模块和网络链路完成；接收上传、提供网页，由 Flask 服务器完成；查看实时温度和历史记录，是浏览器或手机端完成。

学生完成硬件搭建与模块功能匹配并提交。

过渡语：

> 硬件链路只说明“能连起来”，但系统真正怎么工作，要看程序。下面进入软件分析。

## 三、软件分析：读代码，不靠猜（约 12 分钟）

教师切换到活动页“软件分析”。

教师：

> 软件分析分两层。上面是智能终端（micro:bit）代码，左边读代码，右边回答问题；下面是 Flask 服务端代码，同样左边读代码，右边回答问题。大家先读，再填，不要直接猜。

教师指向智能终端代码。

教师：

> 先看网络参数。WiFi 名称和密码对应画布中的路由器；服务器 IP 和端口对应 Web 服务器；上传路由决定智能终端把数据发到服务器的哪个接口。

教师提问：

> 智能终端上传温度时，GET 请求里带了哪两个参数？

预期学生：id 和 val。

教师追问：

> id 表示什么？val 表示什么？

预期学生：id 表示传感器编号，val 表示温度值。

教师：

> 对。这里要特别注意，不是只访问服务器 IP 就能上传数据，还要带上传路由和参数。活动页里“服务器端接收上传数据的路由”不要看提示，要从 Flask 代码中找。

教师指向阈值判断代码。

教师：

> 再看阈值变量。程序把当前温度和 TEMP_THRESHOLD 比较。温度高于阈值时，执行器应当被控制；温度回落后，执行器应当停止。

教师提问：

> 这段代码里，读取传感器使用哪个引脚？控制蜂鸣器使用哪个引脚？

预期学生：读取 P1，控制 P2。

教师切换到 Flask 代码。

教师：

> Flask 端有两个重点。第一个是 /upload，用来接收智能终端上传的 id 和 val；第二个是 /，浏览器访问首页时用来查询并渲染温度记录。

教师提问：

> Flask 从哪里取到 id 和 val？

预期学生：request.args.get('id') 和 request.args.get('val')。

教师：

> 这说明本课上传接口按 GET 查询参数设计。活动页里的相关题目都要从代码中找依据，不要凭记忆写。

教师提示学生完成软件分析并提交。

过渡语：

> 代码看懂后，下一步不是马上说“系统成功了”，而是运行验证。真实系统经常会遇到数据不显示、报警不动作的问题，所以我们要学会排查。

## 四、运行排错：用现象定位环节（约 12-15 分钟）

教师切换到画布的“运行仿真”。

教师：

> 运行前先确认三件事：智能终端代码已经生效，Flask 服务已经启动，数据链路开关处于开启状态。现在点击运行。

教师引导学生观察日志：

> 如果没有数据，第一步不要去改数据库，也不要乱改 IP。先回到数据源：传感器 DATA 接在哪里？代码 read_analog 读的是不是同一个引脚？

学生在活动页“运行排错”记录传感器 DATA 和蜂鸣器 IO 的实际引脚。

教师：

> 现在把温度调高到超过阈值，观察两件事：第一，数据库或浏览器是否出现高温记录；第二，蜂鸣器是否响应。这个问题活动页里要填写：温度高于阈值后，执行器是否正常执行？

如果蜂鸣器正常响：

> 说明从采集、阈值判断到执行器控制这一条链路是通的。接下来再看浏览器页面能不能正确显示数据。

如果蜂鸣器不响：

> 现在我们不要把原因直接归到服务器。请看证据：如果 value 已经超过阈值，alarm 已经为 1，Flask 也返回 BUZZER_ON，说明服务器判断已经完成。问题范围就收缩到智能终端控制蜂鸣器的代码引脚、蜂鸣器 IO 连线，或者执行器组件本身。

教师板书排查顺序：

> 数据不来：传感器 DATA → 读取引脚 → IoT/WiFi → Flask /upload → 数据记录。
> 数据来了但不报警：阈值判断 → 控制引脚 → 蜂鸣器 IO → 执行器状态。
> 数据有但页面不显示：浏览器 URL → Flask 首页 / → 查询与渲染。

教师：

> 现在请大家完成活动页运行排错部分。浏览器地址栏要自己根据服务器 IP、端口和首页路由推出来，活动页不会给正确答案。

学生完成运行排错并提交。

## 五、知识总结：回扣五个组成部分（约 5 分钟）

教师：

> 最后我们把这个系统放回信息系统框架。人是谁？硬件有哪些？软件在哪里？网络体现在哪些地方？数据从哪里产生、怎么传输、最后怎么被使用？

学生回答，教师整理：

- 人：设计、搭建、维护系统的人，值班查看数据的人，课堂中操作和排查的学生。
- 硬件：智能终端、温湿度传感器、蜂鸣器、IoT 模块、路由器、服务器、数据库设备、访问终端。
- 软件：智能终端（micro:bit）程序、Flask 服务端程序、网页展示逻辑、数据库管理逻辑。
- 网络：WiFi、IoT 模块、路由器、IP、端口、HTTP GET 请求、URL 参数。
- 数据：温度值、传感器编号、报警状态、时间记录、页面查询结果。

教师总结：

> 复习信息系统题目时，不要只背设备清单。要沿数据流思考：数据从哪里来，谁处理，怎么传到服务器，保存在哪里，谁查看，哪个环节出错会造成什么现象。

教师：

> 请大家在导学案最后完成自我评价。不是给自己随便打分，而是判断自己能不能独立说清楚引脚、URL、阈值、执行器响应和故障排查。

## 六、课堂预设与应对话术

学生沉默时：

> 先不说设备名，只说“系统要感知什么”。从“温度变化”往回推，传感器就出来了。

学生把 IoT 模块说成智能终端时：

> 智能终端负责运行程序、读传感器、控执行器；IoT 模块负责帮它联网发送请求。两个都重要，但功能不一样。

学生一上来就问正确 URL 时：

> 先从代码找三部分：服务器 IP、端口、首页路由。把三部分拼起来，就是浏览器应访问的地址。

学生看到蜂鸣器不响就说服务器坏了：

> 先看证据。如果数据库有高温记录，Flask 也返回 BUZZER_ON，服务器已经完成判断。问题更可能在执行器控制引脚、蜂鸣器连线或执行器组件。

课堂时间不足时：

> 软件分析保留 WiFi、IP、端口、路由、id、val、阈值、引脚八个核心点；拓展思考留作课后。
