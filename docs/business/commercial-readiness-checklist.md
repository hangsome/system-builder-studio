# 商业版落地检查清单

## 目标

在 `main` 分支具备“可售卖、可激活、可交付、可运维”的最小闭环。

## A. 上线前必须完成（Blocking）

1. 域名与 HTTPS 就绪。
2. 前端与 API 可通过公网域名访问。
3. `simu-api/.env` 已替换真实 `ADMIN_SECRET`、`WEBHOOK_SECRET`、`PRODUCT_*_IDS`。
4. 发卡平台回调已联调通过：`/api/webhooks/card-platform`。
5. 激活主链路已验证：`/api/activate`、`/api/verify`。
6. 管理后台已验证：生成、查询、撤销、导出。

## B. 上线后 1-2 周补齐（Hardening）

1. API 限流策略（按 IP 与按接口）。
2. 后台操作审计日志（生成/撤销记录）。
3. 数据库自动备份（每日）与恢复演练。
4. 密钥轮换机制与过期策略。
5. 监控告警（进程状态、异常日志、磁盘容量）。

## C. 验收用例矩阵

1. `personal`：同设备重复激活成功，第二设备激活失败。
2. `teacher`：最多 3 台设备激活成功，第 4 台失败。
3. 回调幂等：同一订单重复回调不重复发码。
4. 异常签名：错误签名回调被拒绝。
5. 后台导出：CSV 包含类型、状态、设备数、创建时间。

## D. 发布门槛

1. 所有 Blocking 项完成。
2. 验收矩阵全部通过。
3. 公众号首发内容已准备并有成交入口。
